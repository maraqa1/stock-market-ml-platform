# Profitability Attribution Layer

This read-only diagnostic layer summarizes the unified paper trade ledger into profitability slices.

It does not change model scoring, candidate selection, gates, thresholds, order sizing, execution behavior, or live trading state.

## Inputs

The layer uses `trade_ledger_*.csv` generated by `scripts/build_trade_ledger.py`. The CLI can also build a fresh ledger for a date or date range before attribution.

## Automation

`scripts/run_post_nightly_diagnostics.py` refreshes profitability attribution after rebuilding the unified trade ledger. This is read-only and does not alter trading thresholds, model scoring, order sizing, or execution behavior.

## Output Slices

The attribution CSV includes grouped metrics for:

- all trades
- long vs short
- candidate source
- strategy mode
- event session mode
- actual submission session mode
- position status
- exit reason
- model score bucket

## Key Metrics

Each slice reports trade count, open/closed count, long/short count, realised P&L, unrealised P&L, total P&L, average returns, win rate, lineage quality, low-confidence count, and insufficient-data count.

## Interpretation

`NOT_ENOUGH_TRADES` means there are no ledger trades yet. `OPEN_TRADES_ONLY` means attribution can describe current exposure but cannot judge realised edge. `PARTIAL_ATTRIBUTION_ONLY` means some trades rely on low-confidence lineage. `FIT_FOR_ATTRIBUTION` means grouped P&L can be used for strategy review.
