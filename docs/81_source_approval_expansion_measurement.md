# Source Approval Expansion Measurement

This diagnostic measures the existing `source_approval_expansion` lever without changing trading authority.

The config remains:

```yaml
source_approval_expansion:
  enabled: false
  mode: diagnostic_only
```

Ticket 13 classifies each daily candidate row into:

- `source_approved`: already authorized by the source direction today.
- `expansion_eligible`: would pass the conservative long-only expansion conditions, but remains non-executable.
- `still_blocked`: fails source approval and expansion conditions.

Ticket 14 compares forward paper outcomes for those three buckets using counterfactual forward returns. The verdict remains `INSUFFICIENT DATA` until the expansion set has enough 5-day forward outcomes for review. No report generated by this diagnostic promotes candidates, loosens gates, enables shorts, or changes live/paper trading behavior.

Run:

```bash
PYTHONPATH=src /opt/jupyter-env/bin/python3 scripts/run_source_approval_expansion_measurement.py
```

Outputs:

- `data/trading/diagnostics/source_approval_expansion_measurement_detail_YYYYMMDD_HHMMSS.csv`
- `data/trading/diagnostics/source_approval_expansion_measurement_summary_YYYYMMDD_HHMMSS.md`
- `data/trading/diagnostics/source_approval_expansion_edge_test_YYYYMMDD_HHMMSS.csv`
- `data/trading/diagnostics/source_approval_expansion_edge_test_summary_YYYYMMDD_HHMMSS.md`

Materiality:

This is measurement-only and expected non-material because it writes diagnostics only and does not modify configuration, candidate execution status, order submission, or the frozen Segment 1 lane.
